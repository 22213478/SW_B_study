## 학습 약속 (이 저장소의 핵심)

문제를 **맞히는 것**이 목표가 아니다. **완전히 이해하고 내 것으로 만드는 것**이 목표다.

노트(.md)를 쓸 때 반드시 넣을 것:

0. **문제 링크** — 맨 위. SWEA `problemDetail` URL
1. **왜 이 방법을 쓰는가** — 다른 방법(예: DFS, 배열 전체 스캔)과 비교해서
2. **왜 이 자료구조인가** — 큐를 쓰는 이유, 스택이면 안 되는 이유
3. **동작이 어떻게 흐르는가** — 한 턴씩, 큐/방문 배열이 어떻게 바뀌는지
4. **손으로 따라갈 수 있는 작은 예시** — 실제 문제보다 작은 격자로
5. **이 문제에서 실수하기 쉬운 지점** — 방문 시점, 벽/길 숫자, 실패 시 반환값 등
6. **다음에 어디에 다시 쓰는가** — 지금 배운 조각이 본문제(빙하)에서 어떻게 쓰이는지

짧게 요약만 적지 않는다. 나중에 이 파일만 다시 읽어도 처음부터 설명할 수 있어야 한다.

코드(.java)는 빈 파일로 두고 **직접 전부 채운다.** 노트에 정답 전체를 미리 넣지 않는다. 이해용 뼈대·의사코드·작은 예시는 넣어도 된다.

B형으로 풀 때의 순서: **요구사항 정리 → 함수별 복잡도 → 자료구조 선택 → 작은 예시로 손시뮬 → 그다음 코드.**  
맞추기 전에 “이 함수가 Q번 불릴 때 전체 시간이 되는가”를 먼저 말한다.

## B형 형식 (앞으로 전부 이렇게)

A형처럼 `Scanner`로 맵 읽고 `main`에서 BFS 한 번 돌리는 형식이 **아니다.**

| A형에 가까운 연습 | B형 (목표) |
|-------------------|------------|
| `Solution.java` 하나에 `main` | `UserSolution`만 작성. Main은 제공본 그대로 |
| 입력 한 번에 읽고 답 한 줄 | `init` 후 명령 함수가 **여러 번** 호출 |
| 테케마다 새로 시작 | `init`에서 자료구조를 비우고 다시 쌓음 |
| 시간 = 그 테케 한 번 | 시간 = **모든 함수 호출의 합** |

로컬 파일:

- `Solution.java` — SWEA 샘플 Main. **수정하지 않음**
- `UserSolution.java` — 여기만 작성 (처음엔 빈 파일)

제출 전 `System.out` / `print` 전부 제거.

연습 문제(SWEA 번호 검색): 제출이 `Solution` + `main`이면 **한 파일에 짜도 된다.**  
기출·본문제: `UserSolution` API. Main은 제공본.

## 기출을 가져오는 방법 (에이전트에게 보여줄 때)

자세한 템플릿: [`기출.md`](./기출.md)

SWEA 페이지는 로그인이 필요해서 **링크만 주면 문제를 못 읽는다.**

**가장 좋은 방법**

1. 문제 페이지에서 **텍스트를 복사**한다. (함수 선언, 제약, 규칙)
2. `기출/문제이름.md`에 붙여 넣는다. (`기출/`은 gitignore)
3. 채팅에서 `@기출/문제이름.md` 로 연다.
4. **그림·격자·표**만 스크린샷으로 같은 채팅에 첨부한다.

**같이 가져오면 바로 설계할 수 있는 것**

- 함수 시그니처 (`void init(...)`, 반환형, 인자 이름까지 그대로)
- 제약 숫자: `N` 최댓값, **함수별 호출 횟수**, 값 범위, 시간/메모리
- 각 함수가 하는 일 + 겹침/삭제/우선순위 같은 규칙
- 샘플이 명령 나열이면 그 흐름

**이것만 가져오면 부족함**

- URL만
- 제목만
- 긴 스토리 스크린샷만 (제약 숫자가 빠지거나 잘못 읽힘)

정답 코드는 가져오지 않는다. 원문은 `기출/`에만 두고 **GitHub public에 올리지 않는다.**

5105, 7733 같은 일반 연습 코드는 `연습/`에 둔다.

## 규칙

- **.java 파일은 빈 파일**로만 만든다. 코드는 내가 직접 전부 채운다.
- **.md 노트는 짧게 쓰지 않는다.** 위 [학습 약속](#학습-약속-이-저장소의-핵심)을 지킨다.
- 노트에 정답 프로그램 전체를 미리 넣지 않는다. 왜/어떻게/예시는 충분히 적는다.

## 폴더

연습 문제(1226, 7733)를 `본문제/빙하의이동/` 안에 넣지 않는다.  
BFS·덩어리는 **다음 기출에서도** 다시 쓴다. 빙하 폴더에는 빙하만 둔다.

```
README.md                 ← 로드맵
기출.md                   ← 원문 가져오는 방법
기출/                     ← Pro 원문 dump. git 안 올림

연습/                     ← SWEA 번호 문제. 개념 단위로 재사용
  1226-미로1/
    노트.md
    Solution.java
  7733-치즈도둑/
    노트.md
    Solution.java

본문제/                   ← 기출 하나 = 폴더 하나
  빙하의이동/
    노트.md
    UserSolution.java
```

다음 기출이 생기면 `본문제/문제이름/` 만 추가한다.  
그 기출을 위해 번호 문제를 더 풀면 `연습/번호-이름/`에 둔다.

Java 빨간 줄(패키지 불일치)이 나면 `.vscode/settings.json`의 `java.project.sourcePaths`에 그 폴더를 한 줄 더 넣는다. SWEA는 패키지를 쓰지 않는다.
