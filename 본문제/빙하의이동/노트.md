# Day 3. [Pro] 빙하의 이동 — 지금은 융해만

- 문제: SWEA `2026 SSAFY Pro 클럽`에서 `[Pro] 빙하의 이동`
- 언어: **Java**
- 상태: 원문 대기 → `init` + **융해만**
- 목표: 치즈에서 익힌 “남은 칸 덩어리”에, **바다와 맞닿은 칸이 동시에 녹는 것**만 붙인다. 이동·병합은 아직 안 짠다.
- 코드: `UserSolution.java`만 작성. Main은 SWEA 제공본 그대로.

문제 링크는 로그인 페이지라 여기 못 건다.  
원문(함수 시그니처, 제약, 융해 규칙)은 `기출/빙하의이동.md`에 붙여 두고 채팅에서 `@`로 연다. 정답 코드는 넣지 않는다.

## 왜 융해만 먼저인가

이 문제는 대략 세 덩어리다.

1. **융해** — 일부가 바다(빈 칸)가 된다
2. **이동** — 덩어리가 한 방향으로 밀린다
3. **병합** — 겹치거나 맞닿으면 합쳐진다

한 번에 세 개 다 짜면, 답이 틀렸을 때 어디가 잘못인지 모른다.  
치즈까지 온 이유는 1번 다음 “남은 게 몇 덩어리인가”를 이미 갖고 있기 때문이다.

이번 단계의 성공 기준:

- `init` 후 융해를 적용했을 때, 맵이 문제 규칙대로 바뀐다
- 남은 얼음에 치즈와 같은 BFS를 돌리면 덩어리 수가 맞다
- 이동은 아직 없어도 된다

---

## 치즈와 뭐가 다른가 (녹는 조건)

치즈: 맛이 날짜와 같으면 그 칸이 사라진다. 이웃이 바다인지 안 본다.

빙하: **바다와 맞닿은 얼음만** 녹는다. (정확한 양·조건은 원문)

공통:

- 사라진 칸은 길(얼음)이 아니다
- 덩어리 = 남은 얼음을 상하좌우로 이은 무리
- 구멍만 생기면 덩어리가 늘어나지 않는다. **변으로 끊겨야** 늘어난다

```
치즈 day 1          빙하 한 턴
1 이 전부 사라짐     바깥 바다에 붙은 칸만 후보
```

1226 BFS, 7733 “미방문 남은 칸에서 BFS → +1”은 그대로 가져온다.

---

## 왜 동시에 갱신해야 하는가

한 칸을 녹이자마자 맵을 `0`으로 바꾸면, 같은 턴에 **방금 바다가 된 칸**이 옆칸의 이웃 바다로 잡힌다. 그건 다음 턴의 일이다.

치즈에서 맵을 `0`으로 지워도 됐던 이유: 그날 먹을 칸이 “맛 == day”로 **미리** 정해져 있었다. 옆칸을 봐서 먹을지를 정하지 않았다.

빙하는 “지금 맵에서 바다가 몇 칸 붙었나”로 녹는지를 정한다.  
그래서 **한 턴의 녹음을 다 계산한 뒤에**, 한꺼번에 반영한다.

손 예시 (이해용, 원문과 숫자가 다를 수 있음):

```
지금:
0 1 0
1 1 1
0 1 0
```

`0`이 바다라고 치면, 가운데 `1`은 네 방향이 다 얼음일 수도 있다.  
먼저 가장자리를 0으로 바꿔 버리면, 가운데가 **같은 턴에** 바다와 닿은 것처럼 보인다.

흐름:

```
1) 지금 맵만 보고, 각 얼음 칸이 얼마나 녹는지 적는다 (다른 배열 또는 리스트)
2) 그 다음에 맵을 고친다
3) (확인용) 남은 얼음 덩어리 수 = 7733과 같은 BFS
```

---

## 원형 격자 `(y + N) % N`

1226·7733은 격자 밖이면 `continue`였다.

빙하는 위쪽이 아래와 이어질 수 있다. (원문에 원형이라고 되어 있으면)

```
ny = (y + dy[d] + N) % N
nx = (x + dx[d] + N) % N
```

Java에서 `-1 % N`은 `-1`이 되므로, **`+ N`을 먼저** 더한다.

범위 if로 자르면 원형이 깨진다. 이번엔 “밖”이 없다.

---

## 함수를 어떻게 두나 (제출용으로 쪼개는 것)

연습 문제처럼 `main` 안에 다 넣는 방식이 **여기선 불가능**하다. Main은 이미 있고, 우리가 채울 구멍은 문제 API뿐이다.

대략:

- `init` — 맵·크기 저장. 이전 테케 쓰레기 비우기
- 융해 API — 한 턴 동시 갱신만
- (나중에) 이동, 병합
- 덩어리 BFS는 **헬퍼**. 채점이 직접 부르지 않아도 된다

시그니처 이름은 원문 그대로여야 컴파일된다. 추측해서 만들지 말 것.

---

## 자주 하는 실수 (융해 단계)

| 실수 | 결과 |
|------|------|
| 스캔하면서 바로 0으로 | 같은 턴에 안쪽까지 녹음 |
| 범위 `if`로 밖을 자름 | 원형이면 위-아래가 안 붙음 |
| `-1 % N` | 음수 인덱스 |
| 치즈처럼 숫자==날짜로 삭제 | 바다와 무관하게 녹음 |
| 먹힌 칸을 BFS 길로 | 7733에서 이미 한 번 틀린 것 |
| `init`에서 이전 테케 맵을 안 지움 | 다음 테케가 오염 |
| 이동까지 한 번에 작성 | 융해가 틀린지 모름 |
