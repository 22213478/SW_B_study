# Day 2. SWEA 7733 치즈 도둑 (Java)

- 문제: [SWEA 7733. 치즈 도둑](https://swexpertacademy.com/main/code/problem/problemDetail.do?contestProbId=AWrDOdQqRCUDFARG)
- 언어: **Java**
- 상태: **통과**
- 목표: **한 덩어리를 BFS로 칠하고, 그걸 여러 번 해서 덩어리 개수를 센다.** 날짜가 지나면 칸이 사라지는 감각까지.
- 코드: `main`은 입력·출력만. 로직은 함수로.

---

## 문제 요약

- `N × N` 격자. `N`은 2 이상 100 이하. **이번엔 크기가 고정이 아니다.**
- 칸마다 맛있는 정도 `1 ~ 100`
- `X`번째 날, 맛이 **정확히 `X`인 칸**이 먹힌다. (사라진 칸)
- 덩어리 = 아직 남은 칸끼리 **상하좌우**로 이어진 한 무리 (대각선은 아님)
- **100일 동안** 덩어리 개수가 가장 클 때의 그 개수
- 테스트케이스 수 `T`가 입력으로 온다. (1226처럼 10 고정이 아님)

출력:

```
#1 2
#2 1
```

---

## 1. 1226에서 가져오는 것 / 이번이 다른 것

| | 1226 미로1 | 7733 치즈 도둑 |
|--|------------|----------------|
| BFS 한 번이 하는 일 | 시작점에서 도착까지 **길이 있나** | 한 칸에서 시작해서 **이어진 남은 칸을 전부 방문** |
| BFS를 몇 번 | 테케마다 **1번** (시작점 하나) | 그날의 **덩어리마다 1번** |
| 벽 | 처음부터 `1` | 그날 이미 먹힌 칸 |
| 끝나는 조건 | `3`을 보면 성공 | 큐가 빌 때까지 (도착 없음) |
| 답이 되는 값 | 0 또는 1 | 덩어리 개수의 **최댓값** |

1226의 큐·방문·4방향은 그대로 쓴다.  
이번 문제의 핵심은 **BFS를 “한 덩어리 칠하기”로 쓰는 것**이다.

---

## 2. 그냥 이중 for로 풀 수 있나?

**남은 칸이 몇 개인가**는 이중 for로 된다.

```
남은 칸 수 += (맛이 날짜보다 크면 1)
```

이건 답이 아니다. 묻는 것은 **몇 덩어리인가**다.

```
2 1 2
```

1이 먹힌 뒤 남은 칸은 2개다.  
덩어리는 **2개**다. 가운데가 끊겼으니까.

```
2 2 2
```

남은 칸은 3개. 덩어리는 **1개**. 서로 옆칸이니까.

칸 개수와 덩어리 개수는 다른 질문이다.  
그래서 “남은 칸을 발견하면, 그 칸과 **이어진 칸을 한꺼번에 방문**”하는 탐색이 필요하다. 그게 BFS다.

---

## 3. 왜 BFS를 여러 번 돌리나

한 번의 BFS는 **지금 서 있는 칸과 같은 무리만** 본다. 벽(먹힌 칸) 너머는 안 간다. 1226과 같다.

격자에는 무리가 여러 개일 수 있다.

```
아직 방문 안 한 남은 칸을 발견
    → 여기서 BFS 한 번 → 그 덩어리 전체를 방문 처리
    → 덩어리 개수 +1
다음 미방문 남은 칸을 발견
    → 또 BFS
    → +1
```

바깥의 이중 for는 “새로운 덩어리의 **시작점**을 찾는 것”이다.  
안쪽 BFS는 “그 시작점에서 같은 덩어리를 다 칠하는 것”이다.

시작점이 정해져 있던 1226과 여기가 갈린다. 치즈는 **남은 칸이면 어디든** 새 시작점이 될 수 있다.

DFS로 칠해도 개수는 같다. 그래도 지금은 1226에서 익힌 **큐 BFS**를 그대로 쓴다. 빙하에서도 같은 도구다.

---

## 4. 날짜가 하는 일 — 먹힌 칸은 그날의 벽

맵 숫자를 매일 지울 필요는 없다.  
그날 `day`에 **남은 칸**의 정의만 바꾸면 된다.

```
맛이 day보다 크다  →  아직 남음  →  길
그 외              →  이미 먹힘  →  벽
```

`X`번째 날에 맛이 `X`인 칸이 먹힌다.  
1일 끝나면 맛 1이 없고, 2일 끝나면 맛 1과 2가 없다.  
그래서 `day`일이 지난 뒤 남은 칸은 `map[y][x] > day` 이다.

원본 배열을 `0`으로 바꿔 가며 지워도 되지만, 그러면 날짜를 되돌릴 수 없다.  
**원본은 그대로 두고**, 비교만 `> day`로 하는 쪽이 덜 꼬인다.

### 왜 날짜마다 `visited`를 새로 만드나

어제의 방문은 어제의 맵 기준이다.  
오늘은 칸이 더 사라져서 **연결이 달라진다.**

어제 한 덩어리였던 것이 오늘은 두 덩어리일 수 있다.  
어제 방문했다고 오늘 건너뛰면, 새로 쪼개진 쪽을 안 센다.

매일:

1. `visited`를 전부 `false` (새 배열을 만들면 됨)
2. 남은 칸 + 미방문이면 BFS
3. 그날 덩어리 수를 어제까지의 최댓값과 비교

---

## 5. 동작이 어떻게 흐르는가

```
맵은 한 번만 읽는다. 숫자는 안 지운다.

day = 0 .. 100  (또는 맵에 있는 맛의 최댓값까지)
    visited 새로
    chunks = 0
    모든 칸 (y, x):
        남은 칸이고 아직 방문 안 했으면
            bfs(y, x)     ← 이 덩어리 전부 방문
            chunks += 1
    answer = max(answer, chunks)

bfs(sy, sx):
    1226과 같은 큐 BFS
    갈 수 있는 칸 = 범위 안 + 남은 칸 + 미방문
    도착점은 없다. 큐가 빌 때까지 칠하기만 한다.
    넣을 때 방문 표시.
```

바깥 루프가 **날짜**, 그 안 이중 for가 **새 덩어리 시작점**, 그 안 BFS가 **한 덩어리**.

## 6. 손으로 따라가는 예시

이해용 **3×3**. 실제 `N`은 최대 100.

```
1 2 1
2 1 2
1 2 1
```

### day = 0 — 아직 아무도 안 먹음

남은 칸 = 전부. 전부 옆칸으로 이어져 있다.

`(0,0)`에서 BFS 한 번이면 9칸이 다 방문된다.  
다른 칸은 이미 방문 → 새 BFS 없음.

```
chunks = 1
```

### day = 1 — 맛 1이 먹힘

남은 것(맛 2)만 보면:

```
. 2 .
2 . 2
. 2 .
```

`(0,1)`의 상하좌우는 전부 `.` 또는 밖이다. 다른 2와 **변으로 안 닿는다.**  
`(1,0)`, `(1,2)`, `(2,1)`도 서로 대각선이거나 한 칸 떨어져 있다.

BFS를 네 번 시작한다. 매번 칸 하나만 칠하고 끝.

```
chunks = 4
```

대각선을 이어진 걸로 보면 여기서 틀린다. **상하좌우만.**

### day = 2 — 맛 2도 먹힘

남은 칸 없음. BFS 시작점 없음.

```
chunks = 0
```

이 예시의 답은 날짜별 `1, 4, 0` 중 큰 값 → **4**.

day 0을 안 보면, 이 맵은 그래도 4가 나와서 우연히 맞는다.  
아래가 day 0을 빼먹으면 틀리는 경우다.

---

## 7. day 0을 빼먹으면

```
5 5 5
5 5 5
5 5 5
```

- day 0: 한 덩어리 → **1**
- day 1~4: 아직 5만 있음 → 계속 **1**
- day 5: 전부 먹힘 → **0**

답은 **1**.

만약 “1일부터만” 세고, 어떤 테케에서 치즈가 하루 만에 다 없어지면 그날부터 0만 나와서 답이 0이 된다.  
**한 번도 안 먹힌 상태(day 0)도 센다.** 덩어리가 항상 1 이상일 수 있다.

전부 먹힌 날은 0이다. 최댓값을 갱신할 때 0으로 덮어쓰지 않으면 된다. (`max`)

---

## 8. 구멍이 뚫려도 한 덩어리인 경우

```
3 3 3
3 1 3
3 3 3
```

day 1에 가운데만 사라진다. 테두리는 고리처럼 이어져 있다.

```
chunks = 1
```

가운데 빈칸을 덩어리로 세면 안 된다. **남은 치즈만** 센다.

빙하도 같다. 녹아서 구멍이 생겨도, 얼음이 변으로 이어져 있으면 한 덩어리다.

## 9. 왜 함수로 나누나

SWEA 제출은 여전히 `class Solution` + `main`이다.  
다만 `main`에 날짜 루프·이중 for·BFS를 한 덩어리로 넣으면, 1226 때처럼 읽기·탐색·출력이 엉킨다.

역할이 세 층이다.

| 함수 | 하는 일 |
|------|---------|
| `main` | `T`, `N`, 맵 읽기. `#tc 답` 출력 |
| 날짜를 돌며 최댓값을 구하는 함수 | `day`마다 덩어리 수를 받아 `max` |
| 그날의 덩어리 개수 함수 | 미방문 남은 칸에서 BFS를 여러 번 |
| BFS 함수 | 한 덩어리만 방문 처리 (반환값 없어도 됨) |

BFS 함수는 1226과 거의 같다. 다른 점:

- 시작점이 인자로 들어온다 (맵에서 `2`를 찾지 않음)
- 도착 `3`이 없다
- “길”이 `0`이 아니라 `map[ny][nx] > day`

1226 코드를 복사한 뒤, 시작/도착/`0이 길`만 바꾸면 안 된다.  
**남은 칸인지**를 `day`와 함께 봐야 한다.

범위 체크는 이번엔 필수다. `N`이 16이 아니고, 테두리가 벽으로 막혀 있지 않다.

---

## 10. 입력에서 헷갈리는 것

```
2          ← T (테케 개수). 1226과 다름
3          ← N
1 2 1
2 1 2
1 2 1
2          ← 다음 테케의 N
...
```

- 한 줄이 공백으로 나뉜 **숫자**다. `nextInt()`로 읽는다. 1226처럼 16글자 문자열가 아니다.
- 테케마다 `N`이 달라질 수 있다. 배열 크기를 16으로 고정하지 말 것.
- 출력 형식만 `#tc 답`으로 1226과 같다.

시간: `N ≤ 100`, 날짜 ≤ 100.  
날짜마다 격자 한 번 + 남은 칸만 BFS → 대략 `100 × N × N`. 충분하다.  
날짜마다 맵을 새로 복사할 필요도 없다.

## 11. 의사코드 (정답 파일 아님 — 직접 .java에 옮길 것)

```
main:
    T 읽기
    테케 1..T:
        N 읽기
        map[N][N] 읽기
        답 = 날짜를 돌며 덩어리 최댓값
        "#tc 답" 출력

최댓값:
    answer = 0
    day = 0 .. 100:
        answer = max(answer, 그날 덩어리 수)
    return answer

그날 덩어리 수(day):
    visited[N][N] = false
    chunks = 0
    y, x 전부:
        남은 칸(map[y][x] > day)이고 미방문이면
            bfs(y, x, day)
            chunks += 1
    return chunks

bfs(sy, sx, day):
    큐에 (sy, sx), 방문 표시
    큐가 빌 때까지:
        (y, x) 꺼내기
        네 방향 (ny, nx):
            범위 밖이면 continue
            이미 방문이면 continue
            먹힌 칸(map[ny][nx] <= day)이면 continue
            방문 표시하고 큐에 넣기
```

## 12. 자주 하는 실수

| 실수 | 결과 |
|------|------|
| 남은 **칸 수**를 답으로 | 이어진 무리를 안 셈 |
| BFS를 격자에서 한 번만 | 두 번째 덩어리부터 누락 |
| `visited`를 날짜 밖에서 한 번만 | 전날 방문 때문에 오늘 쪼개짐을 못 봄 |
| day를 1부터만 | 한 번도 안 쪼개지고 사라지는 테케에서 0 |
| 대각선도 연결 | 덩어리가 줄어듦 |
| `map[y][x] >= day`로 남음 판단 | 그날 먹혀야 할 칸이 남음 |
| 원본을 0으로 지움 | 다음 날짜에 맵이 이미 죽음 |
| `N`을 16으로 고정 / 범위 체크 생략 | 1226 습관. 여기서 인덱스 에러 |
| `T` 없이 10번만 반복 | 입력 형식 다름 |
| 넣을 때가 아니라 꺼낼 때 방문 | 1226과 같은 중복 큐 |

## 13. 빙하의 이동에서 다시 쓰는 곳

치즈: **맛 숫자 ≤ 날짜**인 칸이 매일 사라진다.  
빙하: **바다와 맞닿은 칸**만 녹는다. (녹는 규칙이 더 까다롭다)

공통:

- 사라진 뒤 **남은 칸의 덩어리 개수**
- 미방문 남은 칸에서 BFS → +1
- 구멍만 생겼다고 덩어리가 늘어나지 않음. **연결이 끊겨야** 늘어남

이번 문제에서 손에 넣어야 하는 문장:

> 격자 전체를 돌다가, 아직 방문 안 한 남은 칸을 보면 BFS로 그 무리를 전부 칠하고 덩어리 +1.

녹는 위치를 고르는 로직은 본문제에서 새로 짠다.  
지금은 **쪼개진 뒤 몇 덩어리인지**만 정확히 세면 된다.
